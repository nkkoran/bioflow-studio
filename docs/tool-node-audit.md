# Tool Node Audit

Reviewed: April 21, 2026

This audit is the Phase 8 reference for BioFlow Studio's shipped tool nodes. Official upstream docs are the source of truth, then BioFlow narrows each inspector to the high-signal options that are most important for the workflows we support. Module/version targets below reflect the versions currently pinned in `src/lib/toolRegistry.ts`.

| Node | Official docs | Module/version target | Current BioFlow coverage | Phase 8 core additions / emphasis | Advanced kept collapsed | Intentionally omitted |
| --- | --- | --- | --- | --- | --- | --- |

| `plink2.qc` | [PLINK 2.0 filter](https://www.cog-genomics.org/plink/2.0/filter) | `plink/2.00a3` | `--maf`, `--geno`, `--mind`, `--hwe`, `--make-bed`; filtered PLINK output | QC thresholds remain the default surfaced path; filter-first inspector ordering | `--make-bed` stays available but secondary to the core QC thresholds | Sample/variant thinning, Mendel/sex/founder filters, frequency/count reporting, specialized deduplication flags |
| `plink2.clump` | [PLINK 2.0 postprocessing](https://www.cog-genomics.org/plink/2.0/postproc) | `plink/2.00a3` | Reference genotypes + summary stats inputs; `--clump-p1`, `--clump-p2`, `--clump-r2`, `--clump-kb`, `--clump-snp-field`, `--clump-field`; clump report + extract ranges outputs | Column mapping stays explicit because it is analysis-critical for summary-stat files | Secondary p-threshold and field selection remain available without crowding the header area | Alternate clump annotations/verbose reporting, less common range/report modifiers |

| `regenie.step1` | [REGENIE options](https://rgcgithub.github.io/regenie/options/) | `regenie/3.4` | Genotypes + phenotype + covariates; `--step 1`, `--bt`, `--strict`, `--bsize`, `--lowmem`, `--loocv`, `--chr`, `--phenoColList`, `--covarColList`; prediction output | Added `--strict` and `--chr`; phenotype/covariate column selectors stay visible because they are essential in multi-trait inputs | `--lowmem` and `--loocv` stay advanced/runtime-oriented | Alternative backends, split-l0/prediction staging, advanced block/trait splitting and rare edge-case controls |

| `samtools.sort` | [samtools sort](https://www.htslib.org/doc/samtools-sort.html) | `samtools/1.19` | Alignment input; `-@`, `-m`, `-n`; sorted BAM output | Thread and memory controls remain explicit; name-sort is available for upstream consumers that need it | Name sort stays collapsed behind the main runtime controls | Tag/minimiser/subsort modes, temp-prefix tuning, compression-level flags |
| `samtools.index` | [samtools index](https://www.htslib.org/doc/samtools-index.html) | `samtools/1.19` | Sorted alignment input; `-@`, `-c`; index alongside BAM/CRAM | Added CSI support because it matters for larger references and long contigs | CSI selection remains a simple advanced output toggle | Multi-file `-M`, min-shift tuning, explicit output path control |
| `bwa.mem` | [BWA manual](https://bio-bwa.sourceforge.net/bwa.shtml) | `bwa/0.7.17` | Reference + R1 + optional R2; `-t`, `-R`, `-M`, `-k`; SAM output | Added minimum seed length to cover a common sensitivity/runtime knob | Read-group and short-split marking remain available but not noisy | Gap/open penalties, bandwidth/scoring internals, alternative algorithms/subcommands |
| `fastqc` | [FastQC project page](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/) | `fastqc/0.12.1` | Multi-FASTQ input; `-t`, `--nogroup`, `--extract`; report output | Added `--extract` because it is useful for downstream aggregation and inspection | `--nogroup` and `--extract` stay advanced relative to the default QC run | Custom contaminant/limits files, format forcing, many CLI-only reporting tweaks |
| `multiqc` | [Running MultiQC](https://docs.seqera.io/multiqc/getting_started/running_multiqc/) | `multiqc/1.21` | Multi-report input; `-f`, `--title`, `--filename`; combined report output | Added report title and output filename so runs can produce clearer artifacts | Overwrite remains available but secondary | Module inclusion/exclusion, config-file driven styling, search-depth and data-dir tuning |
| `flow.filterFile` | N/A - BioFlow internal transform node | Internal node | Tabular input; selected columns, row filters, renames, output type, runtime resources; materialized filtered output | Phase 8 adds grouped inspector sections plus an `awk` fast path for TSV/TXT filters, projection, and rename operations, with Python fallback for CSV/regex/unsupported cases | Runtime resources remain visible but secondary | Full spreadsheet-style transforms, joins, aggregates, and CSV quoting edge cases are intentionally left to future dedicated nodes or custom shell |
| `custom.shell` | N/A - BioFlow internal node | Internal node | Arbitrary shell script with `$INPUT`, `${INPUTS[@]}`, and `$OUTPUT`; stdout captured as node output | Phase 8 keeps the inspector minimal and adds stronger SSH-setup messaging so users understand terminal aliases and session persistence when pairing shell usage with remote access | No extra advanced controls added; the value is direct script access | No attempt to mirror a full shell IDE, environment manager, or command builder inside the inspector |

## Notes

- Internal nodes (`flow.filterFile`, `custom.shell`) do not have upstream CLI manuals, so this audit treats the BioFlow implementation itself as the behavior contract.
- The PLINK flag-builder definitions were kept aligned with the registry so the inspector and generated command stay in sync for surfaced association/QC/PCA/scoring options.
- When a parameter was not promoted into the main inspector, the decision was usually to avoid exposing a long tail of rare upstream flags that would make common workflows harder to scan.
